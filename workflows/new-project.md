# คู่มือ: เริ่มโปรเจกต์ใหม่

คู่มือนี้เป็นขั้นตอนการทำงานสำหรับ **เริ่มโปรเจกต์ใหม่ตั้งแต่ศูนย์**
ทุกขั้นตอนผูกกับ Gate System — ห้ามข้ามด่านจนกว่าจะผ่านครบ

==================================================

## ภาพรวมขั้นตอน

```
ขั้นที่ 1: รับงาน (Gate 0)
    ↓
ขั้นที่ 2: ทำความเข้าใจธุรกิจ (Gate 1)
    ↓
ขั้นที่ 3: ออกแบบระบบเบื้องต้น (Gate 2)
    ↓
ขั้นที่ 4: ค้นหาความเสี่ยง (Gate 3)
    ↓
ขั้นที่ 5: ออกแบบ Solution (Gate 4)
    ↓
ขั้นที่ 6: ตัดสินใจ (Gate 5)
    ↓
ขั้นที่ 7: วางแผนการทำงาน (Gate 6)
    ↓
ขั้นที่ 8: ลงมือทำ (Gate 7)
    ↓
ขั้นที่ 9: Review (Gate 8 + 8.5)
    ↓
ขั้นที่ 10: เรียนรู้ (Gate 9)
```

==================================================

## ขั้นที่ 1: รับงาน → Gate 0 - Task Intake

### สิ่งที่ต้องทำ
1. เขียนสรุปสั้นๆ ว่า "งานนี้คืออะไร" ด้วยภาษาตัวเอง
2. ระบุว่าใครเป็นคนสั่ง / ใครเป็นคนใช้
3. ระบุขอบเขตเบื้องต้น — อะไรอยู่ในงาน อะไรไม่อยู่
4. ตรวจสอบว่ามีข้อมูลอะไรที่ยังขาดหายไป

### Output ที่ต้องได้
- สรุปงาน 1-3 ประโยค
- รายชื่อ stakeholder (ผู้มีส่วนได้ส่วนเสีย — คนที่ได้รับผลกระทบจากโปรเจกต์นี้)
- ขอบเขตงานเบื้องต้น
- รายการคำถามที่ยังไม่มีคำตอบ

### ⚠️ Red Flags
- ไม่สามารถอธิบายงานได้ด้วยภาษาตัวเอง → ยังไม่เข้าใจงาน
- ไม่รู้ว่าใครจะใช้ → อาจทำผิดทิศทาง
- มีคำว่า "แค่", "ง่ายๆ", "เร็วๆ" → อาจกำลังรีบเกินไป

→ ดู checklist เพิ่มเติม: `checklists/gate-0-task-intake.md`

==================================================

## ขั้นที่ 2: ทำความเข้าใจธุรกิจ → Gate 1 - Business Understanding

### สิ่งที่ต้องทำ
1. ตอบคำถาม: "ทำไปทำไม?" — business value (คุณค่าทางธุรกิจ) คืออะไร
2. ระบุว่าโปรเจกต์นี้ช่วย: สร้างรายได้ / ลดต้นทุน / ลดความเสี่ยง / เพิ่มประสิทธิภาพ
3. ระบุ user journey (เส้นทางผู้ใช้ — ลำดับขั้นตอนที่ผู้ใช้จะทำในระบบ)
4. ระบุ success criteria (เกณฑ์ความสำเร็จ — อะไรที่ต้องเกิดขึ้นจึงจะถือว่าสำเร็จ)

### Output ที่ต้องได้
- Business case 3-5 ประโยค
- User journey แต่ละประเภทผู้ใช้
- Success criteria ที่วัดได้
- Priority (ลำดับความสำคัญ) ของแต่ละ feature

### ⚠️ Red Flags
- ตอบไม่ได้ว่า "ทำไปทำไม" → ยังไม่เข้าใจธุรกิจ
- ไม่มี success criteria → ไม่รู้ว่าเมื่อไหร่จะเสร็จ
- ทุก feature มีความสำคัญเท่ากัน → ยังไม่ได้จัด priority จริง

→ ดู checklist เพิ่มเติม: `checklists/gate-1-business.md`

==================================================

## ขั้นที่ 3: ออกแบบระบบเบื้องต้น → Gate 2 - System Understanding

### สิ่งที่ต้องทำ
1. ร่างสถาปัตยกรรมเบื้องต้น (architecture sketch)
2. ระบุ components หลัก (ส่วนประกอบ — แต่ละชิ้นส่วนของระบบ เช่น frontend, backend, database)
3. ระบุ data flow (การไหลของข้อมูล — ข้อมูลเดินทางจากไหนไปไหน)
4. เลือก tech stack (ชุดเทคโนโลยี — ภาษา, framework, database ที่จะใช้)
5. ระบุ external dependencies (ระบบภายนอกที่ต้องเชื่อมต่อ)

### Output ที่ต้องได้
- Architecture diagram (แผนภาพสถาปัตยกรรม) แม้เป็นแบบร่าง
- รายชื่อ components + หน้าที่แต่ละตัว
- Data flow diagram (แผนภาพการไหลของข้อมูล)
- Tech stack ที่เลือก + เหตุผล
- รายชื่อ external dependencies

### ⚠️ Red Flags
- เลือก tech stack ก่อนเข้าใจ requirements → เลือกเพราะชอบ ไม่ใช่เพราะเหมาะ
- ไม่มี data flow → อาจพลาด edge case (กรณีพิเศษที่อาจเกิดปัญหา)
- มี dependencies มากเกินไป → complexity สูง, ความเสี่ยงสูง

→ ดู checklist เพิ่มเติม: `checklists/gate-2-system.md`

==================================================

## ขั้นที่ 4: ค้นหาความเสี่ยง → Gate 3 - Risk Discovery

### สิ่งที่ต้องทำ
1. ระบุความเสี่ยงทางเทคนิค — อะไรอาจทำไม่ได้ / ทำยาก
2. ระบุความเสี่ยงทางธุรกิจ — อะไรอาจทำแล้วไม่มีคนใช้
3. ระบุความเสี่ยงทาง operation (การดำเนินงาน) — อะไรอาจทำให้ระบบล่ม
4. ระบุ single points of failure (จุดล้มเหลวจุดเดียว — ถ้าตรงนี้พังจะพังทั้งระบบ)
5. จัดลำดับความเสี่ยง: สูง / กลาง / ต่ำ

### Output ที่ต้องได้
- Risk register (ทะเบียนความเสี่ยง) — ใช้ template จาก `templates/risk-registry.md`
- แผนลดความเสี่ยง (mitigation plan) สำหรับความเสี่ยงระดับสูง
- รายการ unknowns (สิ่งที่ยังไม่รู้) ที่ต้องหาคำตอบ

### ⚠️ Red Flags
- "ไม่มีความเสี่ยง" → คิดไม่ครบ ทุกโปรเจกต์มีความเสี่ยง
- ไม่มี mitigation plan → รู้ว่าเสี่ยงแต่ไม่มีแผนรับมือ
- unknown มากเกินไป → อาจต้องทำ proof of concept (การทดลองทำเพื่อพิสูจน์ว่าทำได้) ก่อน

→ ดู checklist เพิ่มเติม: `checklists/gate-3-risk.md`

==================================================

## ขั้นที่ 5: ออกแบบ Solution → Gate 4 - Solution Design

### สิ่งที่ต้องทำ
1. ออกแบบทางเลือกอย่างน้อย 2-3 ทาง
2. วิเคราะห์ tradeoff (การแลกเปลี่ยน) ของแต่ละทาง
3. ออกแบบ data model (โครงสร้างข้อมูล)
4. ออกแบบ API (ช่องทางสื่อสารระหว่างระบบ) ถ้ามี
5. ระบุ downstream impact (ผลกระทบต่อระบบที่อยู่ถัดไป)

### Output ที่ต้องได้
- Solution options อย่างน้อย 2 ทาง + tradeoff analysis
- Data model
- API design (ถ้ามี)
- Downstream impact analysis

### ⚠️ Red Flags
- มีทางเลือกเดียว → ไม่ได้คิดทางอื่น อาจพลาดทางที่ดีกว่า
- ไม่มี tradeoff analysis → ตัดสินใจโดยไม่มีข้อมูล
- ออกแบบ data model ก่อนเข้าใจ business → โครงสร้างข้อมูลไม่ตรงกับการใช้งานจริง

→ ดู checklist เพิ่มเติม: `checklists/gate-4-design.md`

==================================================

## ขั้นที่ 6: ตัดสินใจ → Gate 5 - Decision

### สิ่งที่ต้องทำ
1. เลือก solution จากทางเลือกที่ออกแบบไว้
2. บันทึก rationale (เหตุผล — ทำไมเลือกทางนี้ ไม่เลือกทางอื่น)
3. บันทึก accepted risks (ความเสี่ยงที่ยอมรับ)
4. ถ้าเข้าเกณฑ์ Owner Escalation → เข้า Owner Review Mode ก่อน
5. บันทึกลง Decision Registry

### Output ที่ต้องได้
- Decision record — ใช้ template จาก `templates/decision-registry.md`
- เหตุผลที่เลือก + เหตุผลที่ไม่เลือกทางอื่น
- รายการความเสี่ยงที่ยอมรับ
- เงื่อนไข (ถ้ามี)

### ⚠️ Red Flags
- ตัดสินใจโดยไม่มี rationale → อาจเป็นการเดา
- ไม่บันทึก → 3 เดือนหลังจากนี้จะลืมว่าทำไมเลือกแบบนี้
- ข้าม Owner Review สำหรับงานที่เข้าเกณฑ์ → ความเสี่ยงสูง

→ ดู checklist เพิ่มเติม: `checklists/gate-5-decision.md`

==================================================

## ขั้นที่ 7: วางแผนการทำงาน → Gate 6 - Planning

### สิ่งที่ต้องทำ
1. แตก task (แบ่งงาน) ออกเป็นชิ้นเล็กๆ ที่ทำเสร็จได้ใน 1-4 ชั่วโมง
2. จัดลำดับ: อะไรต้องทำก่อน (dependencies)
3. ระบุ milestone (จุดตรวจสอบ — จุดที่สามารถหยุดตรวจได้ว่าไปถูกทาง)
4. ระบุ definition of done (เกณฑ์ว่าเสร็จ) สำหรับแต่ละ task
5. ประมาณเวลา

### Output ที่ต้องได้
- Task list พร้อมลำดับ
- Milestones
- Definition of done ต่อ task
- ประมาณการเวลา

### ⚠️ Red Flags
- Task ใหญ่เกินไป (> 4 ชั่วโมง) → แตกไม่ละเอียดพอ
- ไม่มี milestones → ไม่รู้ว่ากำลังหลงทางหรือเปล่าจนกว่าจะเสร็จ
- ไม่มี definition of done → เสร็จแล้วแต่ไม่มั่นใจว่าเสร็จจริง

→ ดู checklist เพิ่มเติม: `checklists/gate-6-planning.md`

==================================================

## ขั้นที่ 8: ลงมือทำ → Gate 7 - Execution

### สิ่งที่ต้องทำ
1. ทำตาม task list ที่วางไว้
2. ตรวจสอบที่ milestone แต่ละจุด
3. ถ้าพบปัญหาที่ไม่ได้คาดไว้ → กลับไป Gate 3 (Risk) หรือ Gate 4 (Design)
4. เขียน test (การทดสอบ) ควบคู่กับการเขียนโค้ด
5. บันทึก decisions ระหว่างทาง (ถ้าเจอสิ่งที่ต้องตัดสินใจระหว่างทำ)

### Output ที่ต้องได้
- โค้ดที่ทำงานได้
- Tests ผ่าน
- เอกสารอัพเดท (ถ้ามีอะไรเปลี่ยนจากแผน)

### ⚠️ Red Flags
- ทำไปเรื่อยๆ โดยไม่ตรวจที่ milestone → อาจหลงทาง
- เจอปัญหาแต่ดันทุรังต่อ → ควรกลับไป re-plan
- ไม่เขียน test → ไม่มีทางรู้ว่าพังเมื่อไหร่

→ ดู checklist เพิ่มเติม: `checklists/gate-7-execution.md`

==================================================

## ขั้นที่ 9: Review → Gate 8 + Gate 8.5

### Gate 8 - Review
1. ตรวจสอบว่าทำตาม success criteria ที่ตั้งไว้หรือไม่
2. ตรวจสอบคุณภาพโค้ด
3. ตรวจสอบ test coverage (ความครอบคลุมของการทดสอบ)
4. ตรวจสอบ security (ความปลอดภัย)

### Gate 8.5 - Architecture Change Review
1. ตรวจสอบว่ามีอะไรเปลี่ยนจาก architecture เดิมหรือไม่
2. อัพเดท architecture docs ถ้ามีการเปลี่ยนแปลง
3. อัพเดท dependency map
4. อัพเดท module map

### Output ที่ต้องได้
- Review checklist ที่ผ่านครบ
- Architecture docs ที่อัพเดทแล้ว (ถ้ามีการเปลี่ยนแปลง)
- รายการ issues ที่พบระหว่าง review (ถ้ามี)

→ ดู checklist เพิ่มเติม: `checklists/gate-8-review.md` และ `checklists/gate-8.5-arch-review.md`

==================================================

## ขั้นที่ 10: เรียนรู้ → Gate 9 - Learning & Coaching

### สิ่งที่ต้องทำ
1. สรุปว่าเรียนรู้อะไรจากโปรเจกต์นี้
2. ระบุ skill gaps ที่ค้นพบ
3. ระบุสิ่งที่จะทำต่างออกไปถ้าทำใหม่
4. บันทึกลง Learning Registry

### Output ที่ต้องได้
- Learning record — ใช้ template จาก `templates/learning-registry.md`
- รายการ skill gaps + แผนพัฒนา
- สรุปบทเรียนสำหรับโปรเจกต์ถัดไป

→ ดู checklist เพิ่มเติม: `checklists/gate-9-learning.md`
