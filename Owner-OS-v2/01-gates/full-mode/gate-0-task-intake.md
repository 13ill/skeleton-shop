# Gate 0 — Task Intake (รับงาน)

> เข้าใจงานที่ได้รับอย่างแท้จริง ก่อนเริ่มทำอะไร

**เป้าหมาย:** ป้องกันการ "กระโดดเข้าไปเขียนโค้ดทันที" โดยไม่เข้าใจงานจริงๆ

---

## 🎯 วัตถุประสงค์

1. เข้าใจงานที่ได้รับ
2. ระบุ stakeholder
3. กำหนดขอบเขต
4. ตรวจสอบ Owner Escalation

---

## ❓ คำถามที่ต้องถาม

### 1. "งานนี้คืออะไร?"

**ทำไมต้องถาม:**
- ถ้าไม่เข้าใจงาน จะทำผิดทิศทาง

**สิ่งที่ได้:**
- ความเข้าใจที่ชัดเจนว่างานคืออะไร

**ตัวอย่าง:**
- "ทำหน้า login" → หน้า login คืออะไร? UI อย่างเดียว? หรือรวม backend?

### 2. "ใครเป็น user?"

**ทำไมต้องถาม:**
- User ต่างกัน = requirement ต่างกัน

**สิ่งที่ได้:**
- รู้ว่าทำให้ใครใช้

**ตัวอย่าง:**
- User = ลูกค้า → ต้องง่าย สวย
- User = admin → ต้องครบ ละเอียด

### 3. "ขอบเขตงานอยู่ตรงไหน?"

**ทำไมต้องถาม:**
- ถ้าไม่กำหนดขอบเขต งานจะบานปลาย (scope creep)

**สิ่งที่ได้:**
- ขอบเขตที่ชัดเจน สามารถพูดได้ว่า "อันนี้ไม่อยู่ใน scope"

**ตัวอย่าง:**
- "ทำหน้า login" → ต้องรวม forgot password ด้วยไหม? social login ด้วยไหม?

### 4. "งานนี้ urgent จริงหรือแค่รู้สึก urgent?"

**ทำไมต้องถาม:**
- ความ urgent ที่เกิดจากอารมณ์จะทำให้ข้ามขั้นตอนสำคัญ

**สิ่งที่ได้:**
- รู้ว่าจริงๆ แล้ว urgent หรือไม่

**ตัวอย่าง:**
- Urgent จริง: Production down, data loss
- Urgent ปลอม: "อยากได้เร็วๆ" แต่ไม่มี deadline ชัดเจน

### 5. "ข้อมูลอะไรที่ยังขาด?"

**ทำไมต้องถาม:**
- ถ้าข้อมูลไม่ครบ จะทำไม่ได้หรือทำผิด

**สิ่งที่ได้:**
- รายการข้อมูลที่ต้องหาเพิ่ม

**ตัวอย่าง:**
- ขาด: UI design, API spec, database schema

---

## ✅ Output ที่ต้องได้

ก่อนจะผ่าน Gate 0 ต้องมี:

1. **Task Description** — งานคืออะไร (1-2 ประโยค)
2. **User** — ใครเป็น user
3. **Scope** — อะไรอยู่ใน scope / อะไรไม่อยู่ใน scope
4. **Success Criteria** — สำเร็จเมื่อไร (วัดได้)
5. **Priority** — High / Medium / Low
6. **Deadline** — เมื่อไหร่ (ถ้ามี)
7. **Owner Escalation** — ต้อง escalate หรือไม่
