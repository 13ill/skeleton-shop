# Problem Definition — นิยามปัญหาก่อนหา Solution

> "ปัญหาที่นิยามดี = แก้ไปแล้วครึ่งหนึ่ง"

---

## 🎯 ทำไมต้องนิยามปัญหาก่อน?

**กับดักที่พบบ่อยที่สุด:** รีบกระโดดไปหา solution ก่อนเข้าใจปัญหาจริง

```
❌ Solution-First (ผิด):
User: "ทำปุ่ม export Excel ให้หน่อย"
Dev: เขียนโค้ด export Excel ทันที
ผลลัพธ์: ลูกค้าจริงๆ แค่อยากดูยอดขายรวม ไม่ต้องการ Excel เลย

✅ Problem-First (ถูก):
User: "ทำปุ่ม export Excel ให้หน่อย"
Dev: "อยาก export ไปทำอะไรต่อครับ?"
User: "เอาไปดูยอดขายรวมแต่ละเดือน"
Dev: "งั้นทำ dashboard สรุปยอดขายเลยดีไหม? ไม่ต้องเปิด Excel"
ผลลัพธ์: แก้ปัญหาจริง ใช้งานง่ายกว่า
```

---

## 🚨 สัญญาณว่ากำลัง Solution-First

- ลูกค้า/คุณ พูดถึง "วิธีทำ" ก่อน "ปัญหา"
- เริ่มด้วย "ทำ [feature] ให้หน่อย" แทนที่จะเป็น "มีปัญหา [X]"
- ยังไม่รู้ว่าใครเดือดร้อน แต่เริ่มออกแบบแล้ว
- ยังตอบไม่ได้ว่า "ถ้าไม่ทำจะเกิดอะไร"

**เจอสัญญาณเหล่านี้ → STOP → กลับไปนิยามปัญหา**

---

## 📋 วิธีนิยามปัญหา

### 1. ถาม "ทำไม" 5 ครั้ง (5 Whys)

```
ปัญหาที่บอก: "อยากได้ปุ่ม export Excel"

Why 1: ทำไมต้องการ export Excel?
→ เพราะอยากดูข้อมูลยอดขาย

Why 2: ทำไมต้องดูใน Excel?
→ เพราะอยากเห็นยอดรวมแต่ละเดือน

Why 3: ทำไมต้องดูยอดรวมแต่ละเดือน?
→ เพราะอยากรู้ว่าเดือนไหนขายดี

Why 4: ทำไมอยากรู้ว่าเดือนไหนขายดี?
→ เพราะอยากวางแผนสต็อก

Why 5: ทำไมต้องวางแผนสต็อก?
→ เพราะของหมดบ่อย เสียยอดขาย

ปัญหาจริง: ของหมดสต็อก ไม่ใช่ "ไม่มีปุ่ม Excel"
Solution จริง: ระบบพยากรณ์/แจ้งเตือนสต็อก
```

### 2. ใช้ Problem Statement Template

```
ใคร (Who):     [ผู้ที่เจอปัญหา]
เจอปัญหาอะไร:   [อธิบายปัญหา]
เมื่อไหร่ (When): [สถานการณ์ที่เกิด]
ส่งผลยังไง:     [ผลกระทบที่วัดได้]
ตอนนี้แก้ยังไง:  [วิธีแก้ปัจจุบัน + ทำไมไม่ดีพอ]
```

### 3. แยก Symptom กับ Root Cause

```
Symptom (อาการ):    ลูกค้าบ่นว่าระบบช้า
Root Cause (ต้นตอ):  query ไม่มี index

❌ แก้ symptom: เพิ่ม loading spinner ให้ดูดีขึ้น
✅ แก้ root cause: เพิ่ม index ใน database
```

---

## 📝 Problem Statement ที่ดี vs ไม่ดี

### ❌ ไม่ดี (คลุมเครือ / solution-first)

- "ระบบช้า อยากให้เร็วขึ้น"
- "ทำ feature chat ให้หน่อย"
- "อยากได้ dashboard สวยๆ"

### ✅ ดี (ชัดเจน / problem-first + วัดได้)

- "หน้า checkout โหลด 8 วินาที ทำให้ลูกค้า 30% ออกก่อนจ่ายเงิน เสียยอด ~20,000 บาท/เดือน"
- "ลูกค้าถามคำถามซ้ำๆ ทาง LINE วันละ 50 ครั้ง พนักงานตอบไม่ทัน เสียเวลา 2 ชม./วัน"
- "เจ้าของดูยอดขายไม่ได้แบบ real-time ต้องรอ accountant สรุปสิ้นเดือน ทำให้ตัดสินใจช้า"

---

## ✅ Problem Definition Checklist

- [ ] รู้ว่าใครเจอปัญหา (who)
- [ ] อธิบายปัญหาได้ชัด (ไม่ใช่ solution)
- [ ] รู้ผลกระทบที่วัดได้ (ตัวเลข/เงิน/เวลา)
- [ ] แยก symptom กับ root cause แล้ว
- [ ] ถาม "ทำไม" จนเจอต้นตอจริง
- [ ] รู้ว่าถ้าไม่แก้จะเกิดอะไร (cost of inaction)
- [ ] ยังไม่ได้ตัดสินใจ solution (รอ Gate 4)
